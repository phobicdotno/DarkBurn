# Bug hunt notes

Known problems to fix in the final bug hunt. Remove a line when its fix is committed.

- [ ] LightBurn `.lbrn2` import: confirm bitmap and Y-axis orientation with a real file
- [ ] Rare: the UI suite crashed with an access violation inside `d3d10warp.dll` (the Windows software rasteriser, on one of its own worker threads) while some tests drew a screenshot and others made or destroyed their GPU device. `ui_harness::GPU` now serialises creation, teardown and drawing: 0 crashes in 87 loaded runs, against 3 in 120 with only creation and teardown serialised. It is a driver fault, so if it returns run the UI tests with `--test-threads=1`; the crash dumps are in `%LOCALAPPDATA%\CrashDumps`
- [ ] Job: after the last layer with a Z offset or Z step the head stays at that height when the job ends; the next job then starts from there. Not changed because what Z the job should end at needs a decision (absolute `G0 Z..` versus "relative Z moves only")
- [ ] Job: power scale means two things: on line and fill shapes it is a share of max power, on images a share of the way from min to max power (`job_build::image_inputs`). Pick one
- [ ] Job: lead-in and lead-out are also added to open shapes (on the left of travel), though the settings describe them for closed shapes only (`darkburn-job/src/line.rs`)
- [ ] Offset with the sharp join: a corner past the miter limit is clipped at the limit, not bevelled as `offset.rs` says, and a corner sharper than about 5 degrees stops well short of a true miter (the overlay engine's own limit); the result is a valid outline, only the corner differs
- [ ] Booleans and offsets read a text's stored outline; a text that was never rendered would give its placeholder rectangle (not seen in a test: the text commands render after every change)
- [ ] The Move, Size and Rotate locks of the status bar stop mouse drags and arrow nudges, but not the X, Y, W, H and Rotate fields of the ribbon or the rotate and flip commands; unclear which is meant
- [ ] `cargo fmt --all` also walks into the SolidCraft path dependencies (`..\solidcraft\crates\...`): one run failed there with out of memory. `cargo fmt -p <crate>` stays inside DarkBurn
- [ ] Ruida UDP: a datagram that is sent again because its acknowledge was late (not lost) reaches the controller twice; the protocol has no datagram number, so the driver cannot prevent it. Check on a real controller whether a repeated chunk of a file upload is dropped or stored twice
- [ ] Galvo: a `MoveZ` step sends `abs(mm)` (`machine.rs`, `Step::MoveZ`), so a move down and a move up by the same amount give the same Z word; whether the board takes an absolute position or needs a direction is not known from the sources
- [ ] LightBurn import: shapes that share one `VertID` each get their own copy of the path, and only the number of shapes is limited (2 000 000), not the number of points; a small crafted file (one 100 000 point list, thousands of references) can ask for gigabytes. Not run as a test because it would take that memory on the build machine (`lbrn.rs`, `Reader::path_geometry`)
- [ ] PDF import: the same holds for one large image drawn many times (`Do`): every use is decoded again into its own picture, each up to 64 megapixels (`pdf_import.rs`, `Interp::xobject`); a total pixel budget or one decode per object would stop it. Not run as a test for the same reason
- [ ] `image_render::window` would panic (`clamp(1, 0)`) for a picture with no pixels across; no way to get one in was found
- [ ] Flaky under load: `darkburn` `connections_tests::http_runs_a_job_against_a_loopback_web_server` (the job did not finish over HTTP, connections_tests.rs:649, after 148 s, once in a full run under load; 3 of 3 alone). Read in the second hunt without finding a logic fault: alone the test takes 2.7 s of its three 30 s waits; every request costs the test server three 2 ms sleeps and the worker more, and `HttpTransport` gives a request 5 s before it calls the link lost, so a computer about fifty times slower than usual would fail it either way
- [ ] Adjust Image is slow at the limits: forty mode and DPI changes on a 2 x 1 mm image at 25400 DPI with 1000 halftone cells took over a minute in a test (results were right) Measured in hunt pass 2: the same forty changes straight through the dialog and the pipeline take 1.6 s (0.06 to 0.18 s for 2 million dots a time), so the minute was not spent there; the one slow thing found is Enhance with radius 100, 3.7 s for 2 million dots (a 601-tap blur, twice)
- [ ] Job: a cross-hatch fill cut in reverse starts at the end of its first angle, not where the forward one ends, so the planner's travel estimate for it is a little off (`generate::expand_fill`); only travel, nothing burns wrong
- [ ] AI agents: the token of a confirmation is tied to the command's arguments by comparing them whole now; before it compared a 64-bit FNV hash of them, which can be made to collide on purpose. No collision was built to prove it
- [ ] AI agents: any program on this computer can hold all eight connection slots of the control channel without the token (a hello sent one byte every few seconds keeps a slot for hours; opening new connections does the same five seconds at a time), so the real agent is refused. Unauthenticated connections count against the same limit as logged-in ones (`control/server.rs`, `accept_loop`)
- [ ] AI agents: with file writes allowed (the default) the save and export commands write to any path, DarkBurn's own settings folder included, and overwrite what is there without a question; there is no project folder they are held to. `settings.set` can also point `opts.job_log_dir` anywhere, and the job log of the user's next job is then written there
- [ ] AI agents: `settings.set` can change `opts.update_url`, and `help.check_updates` then fetches that address (https anywhere, plain http on this computer only)
- [ ] AI agents: commands that open a system file dialog when run without a path (`help.support_data`, `file.prefs_export` through the registry form, the `Pick` ones in `file_io.rs`) block the window until the user answers; requests queued meanwhile now time out without running
- [ ] Paste onto a hidden layer: the pasted shapes are selected though nobody can see them (hiding a layer and Unlock now drop such shapes from the selection; Paste was left because it would then seem to do nothing)
- [ ] Rotate field of the ribbon: a flipped shape shows 180 degrees (`arrange::rotation_of` reads the first column of the transform, which a mirror turns round), so typing 0 turns it upside down; unclear what a mirrored shape should show
- [ ] Rotary: `axis_steps_per_mm` defaults to 1 (axis units are steps), so with the defaults one turn of a 50 mm chuck is sent as 1600 axis units; on a G-code machine whose rotary axis counts millimetres the person must enter its steps per mm or the job is about ten times too long. Not changed: it is a setting, and which default is meant is not written down
- [ ] Distribute with shapes that overlap so much that the gap is negative: the ends of the selection can still move a little, because the shapes are laid out by their centres from the left end (`arrange::distribute`); outer two stay whenever the shapes do not swallow each other
- [ ] Cuts / Layers: a hidden layer (Show off) with Output on is still burned (`job_build` looks at Output only); unclear whether hidden layers are meant to burn
- [ ] Recent projects: a project whose file is not there when DarkBurn starts (an unplugged drive, a network folder that is down) is dropped from the list for good (`files::prune_recent`); unclear whether it should stay and be dropped only when picked
- [ ] Preferences import and the shared defaults file bring the AI agents (MCP) block with them, so a file from elsewhere can switch the control channel on and allow hardware; unclear whether that block should stay this computer's, like the recent projects
- [ ] Auto-advance after a job counts a job made from the project that the machine reports finished (Start, and Send where the controller reports it); Save G-code, Save RD file and a preview do not advance. Whether a saved file should count is not written down
- [ ] Check for Updates follows up to three redirects (`updates::check`); whether an https address can be redirected to plain http on another host was not tried (no network in tests)
- [ ] With a window open and the keyboard in a panel field behind it, Tab walks on through every control as before (panels first, then the window); only a walk that starts in the window or with the keyboard nowhere is kept in the window (`tab_focus.rs`)
- [ ] Font list: the search text stays in the box after the list is closed and opened again; Convert to Bitmap: the pixel size shown leaves out the pen width that Outlines adds round the shapes
- [ ] Head camera: "Mark at" is now read as a position in the design and "Head at" as the position the laser reports (turned to the design like Print and Cut); check on a real head camera that this is how the marks are measured
- [ ] Galvo: cut direction and tabs reach a galvo job now, but with Optimize on the board's own path ordering (`darkburn_galvo::geom::order_paths`) may still mark an open path, or a piece between two tabs, from its other end; a `darkburn_galvo::Layer` has no way to say a path must keep its direction
- [ ] Ruida: the jog speed of the Move panel is not sent (a jog step is a rapid move at the controller's own speed). The protocol has an axis move speed word (`C9 06`), but whether a controller applies it to a rapid outside a job is not known from the sources: needs a real controller
- [ ] Job: offset fill is still slow on round shapes, though less: a level of a 170-corner outline takes the overlay engine about 3 ms (`i_overlay` outline, which builds a strip for every side and merges them; a square takes 14 microseconds), and a 0.1 mm fill of a 100 mm circle has 500 levels. The levels are worked out once per job now, not once for planning and once per pass, and side by side on all cores: 4.8 s became 0.7 s for two passes on phobic-overlord, with the same moves. Going faster would mean offsetting each level from the one before, which changes the rings a little
- [ ] Galvo: the kerf direction of a galvo job still looks only at shapes of the same layer for what is a hole (`galvo_job::nest`); the G-code and Ruida jobs count the cut outlines of every output layer now
- [ ] Move panel: on a Ruida controller the finish position is one more move at the end of the job, so the controller's own frame of the job grows to hold it (`RdJob::bounds_mm` counts moves); a file measured from the head (start from current position) cannot hold it and is saved without
- [ ] Cross-machine job test (`cross_machine_tests.rs`): LinuxCNC is not in it (a file-only device with no emulator), a galvo's picture is not compared (it is engraved in depth slices, not dots), and the custom G-code device's power is not compared (its plain emulator counts S against 255 whatever the device's S max)
- [ ] Geometry: `tabs::perforate` never ends when the start offset is not a number or the path's length is infinite (it fills memory), and `tabs::place_tabs` makes as many tabs as it is asked for (a count of thousands of millions takes all memory). Nothing in the app calls `perforate` (the job has its own), and the app's tab count is held to 1000, so neither was changed (`crates/darkburn-geom/tests/hunt4_stress.rs` leaves them out)
- [ ] Add Tabs tool: the mark of a tab placed by hand is drawn at least 0.1 mm long and never shortened (`node_tool::tab_size`), while the job leaves no tabs at all with Tab size 0 and shortens them on a small shape (half the outline at most); the automatic marks follow the job now, the manual ones were left
- [ ] Add Tabs tool: the automatic marks read the layer's main settings; a layer with sub-layers cuts each sub-layer with its own tab settings
- [ ] Languages: the Cuts / Layers, Laser and Move panels, the status bar locks and most dialogs are English only ("Speed", "Max power", "Passes", "Copy", "Paste", "Devices" have Norwegian text under other keys, for the material library and the menus); and "Move to left" in a panel tab's menu puts the English dock name after the translated words (`shell.rs`, `ui.move_to`)
- [ ] Application bar: the Save, Undo and Redo icons beside the menus are drawn dim and do nothing when clicked, though their tooltips name the commands; unclear whether they are meant to be buttons
- [ ] `shape.set_start_point` on an outline with coordinates near the largest number answers with a point that is not a number (`x: null`); such a shape is left out when the project is saved. Only reachable with coordinates of 1e308
- [ ] Dialog defaults and command defaults differ on purpose or not: Grid, Circular and Copy Along Path make a virtual array from the window (ticked by default) and real copies from the command when `virtual` is left out
- [ ] GRBL with laser mode off (`$32=0`): a job started on the connected controller now switches the laser off with every travel move (the controller's own `$32` is read at connect). A saved G-code file for a plain GRBL device cannot know the controller and is written as before (the GRBL-M3 device type is for that), and DarkBurn still shows no warning that laser mode is off
- [ ] G-code machines: every job is written in millimetres now. Before, a Marlin, Smoothieware, Snapmaker, LinuxCNC or custom device whose screen unit was inches got its job in inches (`G20`), which a Marlin without inch support reads as millimetres. A custom G-code machine that needs inch G-code has no setting for it (the library profile has `gcode.units`, the app has no field); add one if it is wanted
- [ ] Images: a black area whose pixels do not sit on the scan lines burns a little smaller than drawn (seen in `arrange_origin_tests`: a 2 mm block of 0.5 mm pixels moved by a third of a pixel burns 3 of its 4 half-millimetre lines). Between two pixel centres the tones are blended in linear light and compared with the threshold as sRGB (`resample.rs` `Area`, `process.rs` `Threshold`), so a dot is black only where it is about 79 % black: up to 0.3 pixel is lost on each edge. Not changed: which way an edge should round is a choice
- [ ] Ribbon X and Y (and the cursor readout): they count from the origin corner, but do not follow "Negative coordinates" or "Swap X and Y" of the device, so on such a machine they are not the numbers the controller shows (`numeric_edits::Frame`, `view::Origin::to_machine` against `MachineGeometry::affine`). Read in the code, not proven with a test; the job itself and "move laser to selection" use the full mapping
- [ ] Job: "Use selection origin" and "remove what is outside the work area" measure the shapes where they are drawn, while the job itself is moved by print and cut or a rotary set-up (`job_build::collect`, `selection_bounds`, `discard_out_of_bounds`); the second also measures against the bed when the job starts from the current position or the user origin. Read in the code in hunt 5, not proven with a test
- [ ] Job: pictures are not moved by the print and cut alignment or the rotary mapping that moves the outlines of the same job (`job_build::image_inputs`). Read in the code in hunt 5, not proven
- [ ] Job: with "Cut selected graphics" the kerf direction only sees the selected shapes, so a selected hole inside an unselected outline is offset as an outside (`job_build::collect`). Read in the code, not proven
- [ ] Job: a layer with two Image sub-layers builds its scan lines from the first Image setting that is on (`job_build::image_inputs`). Read in the code, not proven
- [ ] Job: the planner's 2-opt pass stops on a time budget, so a very large job could come out in a different order when the computer is busy; 300 generated jobs of up to 25 shapes were identical when built twice (`job_hunt5_tests`)
- [ ] Job: a job from the current position cannot be checked against the work area while the head position is unknown (nothing connected): `check_work_area` then says nothing. Read in the code, not proven
- [ ] Frame: lead-ins lie outside the job bounds, so the frame does not go round them (`darkburn-job` `job_bounds`); whether a frame should include them is a decision
- [ ] Frame: `machine.frame` (a rectangle given by numbers) and the material test frame leave the head on the first corner as before; only the job frame from the current position goes back to the start
- [ ] Pause: a custom G-code machine or a GRBL controller with laser mode off (`$32=0`) that holds the laser on with `M3` keeps it on while a paused job stands still; only the machines whose power is a command of its own (Marlin M3/M4/fan) are switched off on pause now (`darkburn-gcodebots/src/line.rs`). Read in the code in hunt 5, not tried on an emulator
- [ ] Marlin job end: the move to the finish position is sent before the laser-off command of the job tail (`line.rs`, job tail); harmless as long as every job ends with its own laser off, which the generated jobs do
- [ ] LightBurn files: text keeps only its words, font, height and left/centre/right; bold, italic, letter and line spacing, top/middle alignment and text on a path are not written or read (`formats.rs`, `lbrn.rs`). The letters as saved are kept until the text is edited, then it is drawn again with plain settings
- [ ] DXF import: TEXT with justification Middle (72=4) is read as Centre with the given vertical; MTEXT rotation goes through `to_degrees()` and its insertion point is not taken through the object coordinate system (`dxf_import.rs`); no file from a real CAD program was at hand to prove either
- [ ] SVG import: a stroke-only shape whose edges lie exactly on the clip edge is dropped whole (a 50x50 outline at the origin clipped by a 20x20 rectangle at the origin gives "nothing in it to import"); `clip_stroke` seems to count the edge as outside
- [ ] SVG import: a path with `fill="none"` and no stroke is left out while a `<line>` with no stroke is kept; an old Inkscape file (90 px per inch) with sizes in bare pixels comes in at 96 px per inch
- [ ] `Shape::image_keys` does not look into `array.source`, so a picture used only by a virtual array's originals may not be counted as used
- [ ] Clipboard and art library content (`Clipboard::from_text`) is pasted without the tidy a project file gets on open; `project::tidy` clamps only the first level of array sources (no failure found: layer access clamps everywhere)
- [ ] Cut library: deleting an entry cannot be undone while the unlinking it causes can
- [ ] Art library: a library file changed by another running copy is overwritten on save when this copy has changes; `ArtLibrary::add` says a folder is made past the end but the index is clamped
- [ ] `restore_autosave` does not run `on_open_project` or open the notes the way File > Open does (may be meant for a restored session)
- [ ] HPGL import: `EA` / `ER` rectangles do not count against the item budget (`hpgl.rs`)
- [ ] Not tested in pass 5 (files): Save As to a path that fails half-way, very long and non-ASCII paths, project files from older versions
