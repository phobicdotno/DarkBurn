# Bug hunt notes

Known problems to fix in the final bug hunt. Remove a line when its fix is committed.

- [ ] LightBurn `.lbrn2` import: confirm bitmap and Y-axis orientation with a real file
- [ ] Rare: the UI suite crashed with an access violation inside `d3d10warp.dll` (the Windows software rasteriser, on one of its own worker threads) while some tests drew a screenshot and others made or destroyed their GPU device. `ui_harness::GPU` now serialises creation, teardown and drawing: 0 crashes in 87 loaded runs, against 3 in 120 with only creation and teardown serialised. It is a driver fault, so if it returns run the UI tests with `--test-threads=1`; the crash dumps are in `%LOCALAPPDATA%\CrashDumps`
- [ ] Linux, the same kind of fault: the UI suite run in parallel can die with a segmentation fault inside the Vulkan loader (`libvulkan.so.1`). Seen on an 8-core computer with loader 1.4.341 and Mesa 26.0.8: most parallel runs of `cargo test -p darkburn`, on main at v0.0.528 as well (4 of 4 under a debugger), so it did not come with a later change. GitHub's Linux runner has not shown it. The crashing thread is each time a test in an ordinary frame: `Queue::write_texture` makes a staging buffer or starts a command buffer, wgpu gives it a debug name (`vkSetDebugUtilsObjectNameEXT`, debug builds only), and for that the loader walks the devices of every instance in the process while another test makes or destroys its own. `ui_harness::GPU` serialises creation, teardown and drawing, but not these uploads. Where it happens the suite passes with `--test-threads=1`, and in parallel with `WGPU_DEBUG=0` in the environment, which switches the debug names off (4 of 4 runs)
- [x] Job: after the last layer with a Z offset or Z step the head stays at that height when the job ends; the next job then starts from there. Not changed because what Z the job should end at needs a decision (absolute `G0 Z..` versus "relative Z moves only"). Done (Q077): the job ends with a Z move back to its start height; G-code writes it as a relative move (`G91`/`G0 Z-..`/`G90`), Ruida gets the Z move back, galvo already returned to 0
- [x] Job: power scale means two things: on line and fill shapes it is a share of max power, on images a share of the way from min to max power (`job_build::image_inputs`). Pick one. Done (Q078): on images the shape's power scale now multiplies the dot power (`ImageInput::power_scale`), so black at 50 % burns at half of max, as on lines
