### 1.3 A Ruida laser (TARGET-02)

A CO2 laser with a Ruida RDC644x-class controller, over Ethernet (UDP) or USB. No Ruida machine is on hand, so this target is tested against an emulator. Protocol in 2b.

### 1.4 What this means for DarkBurn

1. **First target: GRBL over serial** (the Atomstack, 400 x 400 mm, S maximum 1000, laser mode).
2. **The Gweike M3 Ultra cannot be added like a Ruida or GRBL machine.** It is an industrial fibre and CO2 flatbed with an Au3tech NexCut X1 / MCC100 CNC card, a capacitive height follower, gas valves, multi-stage piercing and a 1200 W fibre source. There are two ways to drive it: (a) speak the proprietary MCC100 binary Ethernet protocol, for which the vendor publishes no documents (the owner's phobicMlaserLinux project has framing, CRC, registers, FIFO and a simulator; see 2a), or (b) write `.chf`, DXF or NC files for the vendor software to import (`*.nc`, `*.cnc`, `*.g`). Option (b) is the realistic path. Safety note: a 1200 W fibre cutter with pierce and follower logic must not be driven by hobby-grade motion code.
3. **Ruida support is worth building.** It is the de-facto standard for CO2 machines.
4. **Galvo (EzCad2 / BJJCZ) support is not needed for these targets.** The `EzCad2Driver` folder in a LightBurn install is part of the standard Windows installer since galvo support was added, so finding it says nothing about the hardware a user owns. The board and its driver are covered in 2d.

### 2a. Gweike M3 Ultra — what it is and how it is driven

**Identity (web + local evidence agree):** the Gweike **M3 Ultra** is a **6-in-1 dual-source flatbed**: a **1200 W fiber laser** (1080 nm, CW; the user's unit has a **Max Photonics MFSC-series** source) for sheet-metal cutting, fiber welding, rust removal/cleaning and handheld cutting, plus a **130 W CO2 glass tube** (Koenig AU lists 150 W) for cutting/engraving acrylic, wood, MDF. Official spec: work area **1380 x 920 mm** (travel 1450/960/60 mm), 800 mm/s, 1 G, ±0.02 mm, 610 kg, 100-240 V, air-cooled, Class 4. This is exactly the "CF1390" (CO2 + Fiber, 1300 x 900) package on the user's USB stick; axis soft limits in the parameter dump are 1371 x 950 mm. Family: M3 / M3 Pro = 620 x 620 mm with 800 or 1200 W fiber + 80 W CO2; M3 Max / Ultra = the 1390 frame with 1200 W. No 1500/2000 W option in the M series (Gweike's fiber-only LF1390 goes 1-6 kW).

**Accessories:** optional "Automated Rotary Attachment" (not fitted/configured on the user's machine: `IsRotatingShaft=0`); **no camera**; fiber head has auto-focus + capacitive height follower ("ZF"/FTC) + automatic edge finder; CO2 side has a motorized Z bed (`LiftingPlatformType=1`); integrated air compressor, N2/O2/air assist via proportional valves (DA-controlled, `PGasParam`); fully enclosed table with pass-through for 4x8 sheets; laser source is a separate 620 x 355 x 610 mm box.

**Controller / firmware — not Ruida, not GRBL, not Trocen:** an **Au3tech "NexCut X1" CNC system on the MCC100 / MCC100-MIX motion card** (Wuhan Au3tech Intelligent Technologies Co., Ltd., au3tech.com / au3laser.com / au3tech.cn). Gweike ships Au3tech's host software rebranded as **"Mlaser"** (Gweike download Mlaser-v0.0.1.51_SP1; USB stick v0.0.0.52; upstream NexCut v0.0.0.83). "SC2000" is Au3tech's product line / internal name (PDB `D:\SC2000\NexCut\NexCut_X1_Http`), "HighSea" is only an internal ProgID (no public company). MCC100-MIX is the hybrid variant with a 5 V PWM2 output for the CO2 tube (Au3tech manual §3). Card: 5 pulse axes (X / Y1 / Y2 dual-drive gantry / W / Z), RS485, 2 x 0-10 V DA, 12 DI / 8 DO, 10/100 Ethernet, on-board capacitive FTC height controller (M12 amplifier), 24 V / 10 A; EtherCAT servo variant strings exist in the software. Firmware `MCC100_V201.52.mcf` is encrypted (7.998 bits/byte entropy; CPU architecture not recoverable), uploaded with function code 0x26. The occasional support claim "Ruida 6640y" is wrong — `6640_Y-Cloud` is the LightBurn profile for the Gweike *Cloud* CO2 desktop series. Pendant: XHC PHB02/PHBX wireless handwheel (Fn + "Go to Origin" returns to cutting origin). Au3tech manual parameter-page password "3721".

**Connection: Ethernet only, direct PC <-> card cable.** PC NIC set to 10.1.1.10/24 (Gweike's `IPSet.exe` just runs `netsh interface ip set address ... 10.1.1.10+i`), card at **10.1.1.168**, Z-follower at 10.1.1.169:502 (external FTC) or on-card, fiber source at 10.1.1.170 (port 10001 ASCII, EC3710 Modbus 502), remote telemetry to 47.104.17.21:9001 (Alibaba Cloud, only if `EnableRemoteMonitor`). **No USB serial, no VID/PID, no WiFi** for control. Classic failure in the Gweike forum: Windows "unidentified network" + Mlaser "not connected".

**Card protocol (proprietary; reverse-engineered by the user's own project phobicMlaserLinux, static analysis of NCModule.dll + runtime logs, no capture yet):**
- Transport: **UDP** to `10.1.1.168:502` when `AccessType=1` (shipped), TCP `connect()` when 0. Timeouts `MCTimeout` 500 ms, 2-3 retries, 1 ms send interval.
- Framing (class `CExtModbus`, "Modbus-flavoured", not real Modbus): `[seq u16 BE][CRC16 u16][len u16 BE][unit=0][func][payload LE]`, custom function codes **0x20, 0x21, 0x26 (firmware block write), 0x30 (register block read), 0x40 (register write)**, Modbus-style exception replies (`func|0x80` + exception byte). Real Modbus TCP (`CStdModbus`, FC 3/16) is used only for the EC3710 extension card.
- Register map: 32-bit registers addressed by u32. Groups: 1000 (RO status/alarm words, DI/DO bits, FIFO margin at 1016, frame id at 1015), 2000 (per-axis RO, 5 x 10), 5000 (RW), 10000/11000 (ZF status/properties), 13000/13200 (auto-focus), 50000 (system RW, 26 words incl. IP/mask/gateway and interpolation period 50005), 50200 (per-axis RW, 5 x 20), 59500-59511 (licence block, incl. RTC), 59600+ (hardware parameter blocks). Command registers **0x65 (101) = command vector**, **0x66 (102) = FIFO stream**, **0x67 (103) = FIFO control** (1 clear, 2 start, 3 stop).
- Job streaming: motion is pre-planned on the PC (contour fit, look-ahead, S-curve, 250 µs interpolation period from reg 50005) and streamed as a **FIFO of 12-byte items** via `func 0x40 -> reg 0x66`: `[frameId u32][item0][item1]...`, motion items = 3 x u32 (ticks are motor pulses, X low half / Y high half, carried remainder), interleaved with control records (laser gate DO, PWM `[9999,3,freq,...]`/`[9999,0x11,...]`, DA power `[9999,4,0,mV]` 0-10 V, gas DAs, ZF follower records `103/104/109/118`), frames flushed at ~300 words (~99 items, 1192-byte payload). FIFO starvation is an alarm bit; the PC keeps ~1.6 s of motion queued (`MCFifoTime`).
- Command vectors on 0x65 (LE u32 words): stop `[1,0x1F,2,vd,10*vd]`, per-axis jog/home `[2,...]`, `[3,...]`, DO bulk `[9999,2,mask,value]` (DO5 = fiber gate 0x10, DO6 = red light 0x20, DO9 = CO2 laser), DA `[9999,4,...]`, ZF `[101]` stop / `[103,v*10,h*1000]` move / `[104]` follow / `[107]` calibrate. Pause = Stop. Hardware E-stop = alarm_1 bit 30.
- Laser source link: IPG-YLR-style ASCII on 10001 (`EMON\r`, `EMOFF\r`, `ABN\r`, `ABF\r`, `SDC n\r`) or Raycus variant (`\x1bO\r`, `\x1bCP n\r`), plus Max Photonics Modbus map; on this machine fiber power goes out as DA1 0-10 V (`LaserControlType=3`, `AnalogPowerCoefficient=100`).
- Licensing: card-bound `CDog` (encrypted data area + card RTC via registers 59500-59511); MainApp gates Start / frame / dry-run on licence state; Home / Stop / jog are ungated. Nesting needs a USB HID dongle (VID 3689 PID 8762, AutoNest.dll only).
- Vendor file format: `.chf` ("Craft file", binary, CP936 strings) — round-trip reader/writer exists in phobicMlaserLinux (M0 done). Imports: DXF (the only "Standard file"), `.nc/.cnc/.g/.txt` G-code, PLT.

Not applicable: LaserWeb4 has no Ruida support (Ruida is not G-code). No "RuidaPy"/"RDTools"/"ruida-gcode"/PyPI `ruida` packages exist; the only PyPI Ruida package is `ruida-pa`. Nobody claims a formal clean-room process; all are capture/file-based RE.

**Transport — UDP (data channel):** controller listens on **50200**; host must bind source port **40200** (controller replies there). Jog / "wireless panel" channel: controller **50207**, host source **40207**, unswizzled, no checksum. Datagram = `[2-byte big-endian checksum][swizzled payload]`, checksum = `sum(bytes) & 0xFFFF` over the **swizzled** bytes (MeerK40t `struct.pack(">H", sum(data) & 0xFFFF) + data`; EduTechWiki's "before swizzling" prose is wrong). Max datagram 1472 bytes incl. checksum; MeerK40t/LibLaserCut chunk at ~1000/998 bytes; payload may split mid-command. Reply per datagram = one byte: wire **0xC6 = ACK** (logical 0xCC swizzled with 0x88), wire **0x46 = error** (logical 0xCD); MeerK40t's emulator sends logical 0xCF NAK (wire 0x48) on checksum mismatch and the session resends. Logical 0xCE = ENQ (MeerK40t connects by sending ENQ, expects ACK). Retry rule: resend first chunk on 0x46, abort on later chunks; timeout ~3-4 s. After a `DA 00` query the controller sends ACK **then** a second datagram with the `DA 01 ...` reply. No session/handshake/arbitration; anything valid executes. RDC8445S also accepts TCP on 50200 (ruida-pa).

**Transport — USB:** FTDI **FT245R, VID 0x0403 PID 0x6001**, 8N1, baud effectively irrelevant (115200/38400/921600 all reported working); RTS/DTR asserted (kkaempf: pulse DTR low/RTS high ~5 ms then DTR high/RTS low to start). **No checksum prefix and no ACK byte on USB** — same swizzled command stream; `DA 00` queries return a 9-byte reply. LightBurn's Ruida USB uses the FTDI VCP driver.

**Swizzle (per byte, identical for files and both transports):**
```
encode: a = swap bit0<->bit7 of p;  s = ((a ^ MAGIC) + 1) & 0xFF
decode: b = ((s - 1) & 0xFF) ^ MAGIC;  p = swap bit0<->bit7 of b
```
MAGIC: **0x88** default (RDC644x/6442G/6445, RDLC320/230, 633X/654XG); **0x11** for 634XG; **0x38** RDL9635 (RDCAM v3). EduTechWiki has a card-ID -> magic table (0x6320->0x11, 0x6302->0x83, 0x6300->0x33, 0x6501->0x34, 0x651x->0x77/0x75/0x99/0x13/0x60/0x76/0x10, 0x690f-0x6911->0xA1, 0x7230/7430/7930->0x10). MeerK40t detects magic from the byte histogram (most frequent byte - 1, since 0x00 encodes to magic+1) and by probing `DA 00 05 7E` (card ID) for all 256 magics. No source ties 0x11 to RDC6432 specifically.

**Command families (logical bytes; first byte >= 0x80, params < 0x80).** Encodings: int7, **int14** (2x7-bit, signed 2's-complement for relative coords, unsigned for power), **int35** (5x7-bit, shifts 28/21/14/7/0). Units: coords µm, speed µm/s, time µs, freq Hz, power = pct*16383/100 (0x3FFF = 100 %), color 0x00BBGGRR, cstrings NUL-terminated 7-bit.
- Moves/cuts: `88 X Y` move abs; `89 dx dy` move rel; `8A dx` / `8B dy`; `A8 X Y` cut abs; `A9`/`AA`/`AB` cut rel / relX / relY. Single-axis `80 00 X`, `80 08` Z, `A0 00` Y/A, `A0 08` U.
- Power: `C7/C0/C2/C3 pwr` immediate L1-4; `C8/C1/C4/C5` end power; `C6 01/02` min/max L1, `C6 21/22` L2, `05/06` L3, `07/08` L4; per-part `C6 31/32`, `41/42`, `35/36`, `37/38 part pwr`; `C6 10` laser interval, `11` add delay, `12/13` on/off delay, `15/16` on/off delay 2, `C6 50/51/55/56` through-power, `C6 60 part freq`.
- Speed: `C9 02 spd` layer/cut speed; `C9 03` axis; `C9 04 part spd`; `C9 05` force eng speed; `C9 06` axis move.
- Layer (`CA`): `CA 01 00` layer end; `CA 01 01..04` work mode 1-4; `CA 01 10/11` laser device 0/1; **`CA 01 12/13` air assist off/on**; `14` DB head; `30/31` laser-2 offset; `CA 02 part n` layer number; `CA 03` tube start; `CA 04` X sign map; `CA 05 color`; `CA 06 part color`; `CA 10` ex IO; `CA 22 part` max layer; `CA 41` work mode part.
- Process (`D8`): `D8 00/01/02/03` start/stop/pause/continue; `D8 10/11/12` ref-point / origin mode; `D8 2A/2C/2D/2E` home XY/Z/U, focus Z; `D8 20-27` keydown, `30-37` keyup.
- Rapid/jog (`D9`): `D9 00/01/02/03 opt X` move X/Y/Z/U; `D9 10 opt X Y` move XY; `D9 30` XYU; opt 00 origin, 01 origin+light, 02 none, 03 light.
- Settings: `DA 00 hh ll` read -> reply `DA 01 hh ll <int35>`; write `DA 01 hh ll <int35> <int35 copy>`. Key addresses: `05 7E` card ID (0x65106510 -> RDC6442S), `05 7F` firmware ver, `04 00` machine status (bit0 job running, bit1 paused, bit24 moving), `04 21/31/41/51` current X/Y/Z/U, `00 26/36` bed X/Y, `04 05` file count, `06 20/21` job length/done, `00 11..` PWM freq, `00 12/13` min/max power, `02 00` system settings (0x0000 return origin, 0x4000 no return, 0x8000 abs origin), `0B 11` card lock.
- File/doc: `E8 02` begin file transfer (then `E7 01 <name> 00`), `E8 01 nn` get filename n, `E8 03 n` run stored doc, `E8 00` delete, `E8 04` calc doc time; `E5 00` doc upload page, `E5 02` doc end, `E5 05 <int35>` file sum (byte-sum of commands; LightBurn's differs by a constant 220). `E6 01` set absolute; `E7 00` block end, `E7 03/07` process TL/BR, `E7 04` repeat, `E7 05` array dir, `E7 06` feed repeat, `E7 08` array repeat, `E7 50/51` doc min/max, `E7 52/53` part min/max, `E7 54/55` pen/layer offset, `E7 60` element index, `E7 61/62` part min/max ex; `EA n`/`EB` array start/end; `F0` ref point set; `F1 00..04` element max idx / block cutting / display offset; `F2 xx` element arrays; `D7` EOF.
- Jog channel 50207 (unswizzled): `CC` connect (reply `CC` + `A5 68 ...` position frame), `CE` keepalive, `CD` disconnect, `A5 50 kk` key-down / `A5 51 kk` key-up with kk: 01 -X, 02 +X, 03 +Y, 04 -Y, 0A/0B ±Z, 0C/0D ±U, 05 pulse, 06 start/pause, 07 esc, 08 origin, 09 stop, 0F trace, 11 speed toggle, 12 laser gate, 5A reset; `A5 53 00` frame.

**.rd file format:** no magic/header; a .rd is simply the swizzled command stream (all bytes, magic 0x88 by default), beginning `D8 12`/`D8 10` `F0` `E6 01` `F1 02 00` `D8 00` ... bounds (`E7 03/07/50/51`) ... layer table (`CA 22`, per-layer `C9 04`, `C6 31/32`, `CA 06`, `CA 41`, `E7 52/53/61/62`) ... body (`CA 02`, `CA 01 13`, `C9 02`, `C6 01/02`, cuts) ... trailer `EB E7 00 DA 01 06 20 <dist> <dist> D7`. **UDP/USB upload = the same bytes**, preceded by `E8 02 E7 01 <filename> 00` (LightBurn wraps with `E5 00` / `E5 05` sum), then datagram-chunked with checksum. RDWorks "Download" stores on the controller; "Start" streams `D8 00` or runs `E8 03`.

**Layer parameters in open docs:** speed `C9 02/04` (µm/s); min/max power laser 1 `C6 01/02`, laser 2 `C6 21/22`; air assist `CA 01 12/13` (Schuermans: `CA 01` device-flag bitmask, 0x01 = blower); laser device select `CA 01 10/11`; frequency `C6 60`; color `CA 05/06`; work mode cut/scan/dot `CA 01 01..04`, `CA 41`; laser on/off delay `C6 12/13`; through-power `C6 5x`; layer end `CA 01 00`.

### 2c. GRBL 1.1 (plus grblHAL and FluidNC) over serial

**Serial & banner:** 115200 8N1 (compile default `BAUD_RATE 115200`). Boot/soft-reset banner `Grbl 1.1h ['$' for help]` signals init complete. Send one line terminator consistently (`\r\n` counts as two in GRBL 1.1 -> extra `ok`; grblHAL counts it as one).

**Real-time commands** (single bytes, no newline, never buffered): `?` 0x3F status; `~` 0x7E cycle start/resume; `!` 0x21 feed hold; 0x18 soft reset; 0x84 safety door; 0x85 jog cancel (Jog state only; flushes queued jogs); feed override 0x90 = 100 %, 0x91 +10, 0x92 -10, 0x93 +1, 0x94 -1; rapid 0x95 = 100 %, 0x96 50 %, 0x97 25 %; spindle/laser 0x99 = 100 %, 0x9A +10, 0x9B -10, 0x9C +1, 0x9D -1; 0x9E toggle spindle stop (Hold only); 0xA0 flood, 0xA1 mist. `?` is ignored while one is pending or during homing; poll <= 5 Hz.

**Status report** `<State[:sub]|MPos:x,y,z|FS:f,s|WCO:...|Ov:f,r,s|Pn:XYZPDHRS|Bf:15,128|Ln:n|A:SCFM>`. State first, position second (MPos or WPos, never both — `$10` bit0: 0 = WPos, 1 = MPos; bit1 adds `Bf:`; `$10=3` = MPos+Bf). `WCO` (= WCS + G92 + G43.1) sent every 10/30 reports, on change, and on first report after reset; `WPos = MPos - WCO`. `FS:` = feed, programmed S. `Bf:` = free planner blocks, free RX bytes. `Pn:` triggered pins X Y Z (limits), P probe, D door, H hold, R reset, S start. `Ov:` feed %, rapid %, spindle %. `A:` accessories S/C/F/M. States: `Idle`, `Run`, `Hold:0` (complete) / `Hold:1` (in progress), `Jog`, `Alarm`, `Door:0` closed / `:1` ajar / `:2` open, hold in progress / `:3` closed, resuming, `Check`, `Home`, `Sleep`. `$13=1` -> inches.

**`$$` settings:** $0 step pulse µs, $1 idle delay ms (255 = always on), $2/$3 step/dir invert mask, $4 enable invert, $5 limit invert, $6 probe invert, $10 status mask, $11 junction deviation, $12 arc tolerance, $13 report inches, $20 soft limits (needs homing + $130-132), $21 hard limits, $22 homing enable, $23 homing dir mask (X=1, Y=2, Z=4), $24 homing feed, $25 seek, $26 debounce, $27 pull-off, **$30 max spindle RPM = S value mapped to 100 % PWM (S > $30 clamps), $31 min RPM (S0 -> off), $32 laser mode**, $100-102 steps/mm, $110-112 max rate mm/min (also G0 rate), $120-122 accel mm/s2, $130-132 max travel. `$x=v` writes must be send-response (EEPROM write disables RX interrupt). The Atomstack target: `$30=1000` (S-value maximum 1000 in its stored device profile).

**Laser mode ($32=1):** laser fires only in G1/G2/G3; G0 and G38.x force laser off (but keep modal state). **M3** = constant power regardless of speed (scorches ends; useful for focusing). **M4** = dynamic: PWM scales with instantaneous velocity vs programmed F during accel/decel; off while stationary. S-only changes between consecutive G1/2/3 blocks execute without stopping (PWM updated mid-motion); M3/M4/M5 state change forces a motion stop; `S0` turns laser off mid-move. No spin-up pause in laser mode (with $32=0 GRBL pauses on every S/M change). Jogging inherits laser state — caution. Default PWM 1 kHz. Switch $32=0 before spindle milling.

**Streaming & responses:** every line -> `ok` or `error:N` (line discarded on error). Empty line -> `ok`. Startup-line results print `>line:ok`. *Send-response*: wait for ok before next line (simple, may starve the planner on short segments). *Character-counting* (official `doc/script/stream.py`): RX_BUFFER_SIZE = 128; keep a list of each sent line's length+1; send while `sum < 127`; each `ok`/`error:` pops one entry. Parse the RX size from `[OPT:VNM,15,128]` rather than assuming 128. Caveat: after an error, buffered lines keep executing — pre-validate with `$C` check mode. Push messages: `ALARM:N`, `[MSG:...]` (`Reset to continue`, `'$H'|'$X' to unlock`, `Caution: Unlocked`, `Enabled`/`Disabled`, `Check Door`, `Check Limits`, `Pgm End`, `Restoring defaults`, `Restoring spindle`, `Sleeping`), `[GC:G0 G54 G17 G21 G90 G94 M5 M9 T0 F0 S0]` (from `$G`), `[HLP:...]`, `[VER:1.1h.20190825:]`, `[OPT:...]`, `[echo:]`, `[G54:..]..[G59:] [G28:] [G30:] [G92:] [TLO:] [PRB:x,y,z:1]` (from `$#`). Commands: `$$`, `$x=v`, `$#`, `$G`, `$I` / `$I=str`, `$N` / `$Nx=line`, `$C`, `$X` unlock, `$H` home, `$RST=$|#|*`, `$SLP`. `$J=`: G1-like, needs >= 1 axis word + F every time (F not modal), optional one-shot G20/G21/G90/G91/G53; S/T/other G/M rejected (error:16); accepted only in Idle/Jog; soft-limit violation -> error:15 (not alarm); jogs queue; cancel with 0x85; sync with `G4P0`. GUI jog recipe: short G91 jogs sized s = v*dt (dt 25-60 ms), wait `ok`, send 0x85 on key release.

**Errors:** 1 no letter, 2 bad number, 3 unknown `$`, 4 negative value, 5 homing disabled, 6 step pulse < 3 µs, 7 EEPROM read fail, 8 `$` needs Idle, 9 G-code locked (alarm/jog), 10 soft limits need homing, 11 line too long, 12 step rate too high, 13 door open, 14 build info too long, 15 jog exceeds travel, 16 bad jog, 17 laser mode needs PWM, 20 unsupported G-code, 21 modal group conflict, 22 feed undefined, 23 needs integer, 24 axis-word conflict, 25 repeated word, 26 no axis words, 27 bad N, 28 missing P/L, 29 G59.x unsupported, 30 G53 needs G0/G1, 31 unused axis words, 32 arc no in-plane axis, 33 invalid target, 34 arc radius error, 35 arc no IJK, 36 unused words, 37 G43.1 wrong axis, 38 tool number too big. **Alarms:** 1 hard limit, 2 soft limit (unlockable), 3 reset during motion, 4 probe initial state, 5 probe no contact, 6 homing reset, 7 homing door, 8 pull-off didn't clear switch, 9 switch not found, 10 (1.1h) second switch not found.

**Open-source implementations:** *Balor* (Bryce Schroeder, https://gitlab.com/bryce15/balor, 2021) — GitLab lists "Server Side Public License v1" but the repo root also carries `LICENSE` + `gpl-3.0.txt`; verify before reuse; modules `BJJCZ_LMCV4_FIBER_M.py` (+ `_blobs.py` captured init sequences), `MSBF.py` job format, `command_list.py`, `Cal.py`/`RBFInterpolator.py` (lens correction), `default.cor`, `sender.py`. *MeerK40t* `meerk40t/balormk/` (**MIT**, https://github.com/meerk40t/meerk40t/blob/main/meerk40t/balormk/controller.py, usb_connection.py) — the maintained reference. *galvoplotter* (https://github.com/meerk40t/galvoplotter, pyusb-only controller/connection/spooler/job). *glase* (https://github.com/tinkerator/glase, Go, BSD-3, ComMarker Omni UV; reads/uploads `.cor`, converts `.fixup` -> `.cor`). No Rust/Zig/C implementation exists; knowledge comes from USB captures of EzCad2 (Hackaday 2022).

**Protocol:** 12-byte commands = six LE u16 (word0 opcode, 5 params); opcodes >= 0x8000 are *list* commands batched 256 per 3072-byte packet (`ExecuteList` 0x0005 runs, `EndOfList` 0x8002, `ResetList` 0x0012, `StopList`/`StopExecute`); single commands 0x0001-0x0062 (EnableLaser 0x04, DisableLaser 0x02, GetVersion 0x07, GetSerialNo 0x09, GetListStatus 0x0A, GetPositionXY 0x0C, GotoXY 0x0D, LaserSignalOn/Off 0x0F/0x0E, WriteCorTable 0x15 + WriteCorLine 0x10, SetControlMode 0x16, SetDelayMode 0x17, SetLaserMode 0x1B, SetTiming 0x1C, SetStandby 0x1D, SetPwmHalfPeriod 0x1E, WritePort 0x21, ReadPort 0x25, Fiber_SetMo 0x33, Reset 0x40 ...). List ops: JumpTo 0x8001, MarkTo 0x8005, LaserOnPoint 0x8003, DelayTime 0x8004, JumpSpeed 0x8006, MarkSpeed 0x800C, LaserOnDelay/OffDelay 0x8007/8, MarkFreq 0x800A, MarkPowerRatio 0x800B, MarkCurrent 0x8012, QSwitchPeriod 0x801B, PolygonDelay 0x800F, JumpDelay 0x800D, FiberOpenMO 0x8021, FiberYLPMPulseWidth 0x8026 (MOPA), ReadyMark 0x8051. Galvo space 0..65535 per axis; lens field size -> mm/unit; `.cor` correction table uploaded at init. Fiber: `QSwitchPeriod = 20000/kHz`, power -> `MarkCurrent`; CO2/UV: `MarkFreq = 10000/kHz`, `MarkPowerRatio = 200*power/freq`. "Light" (red pointer) = WritePort bit 8 + jumps; "Mark" = MarkTo with laser enabled.

**Transport:** USB bulk, **VID 0x9588 PID 0x9899** ("BJJCZ USBLMCV4"), interface 0 alt 0, OUT endpoint 0x02, IN endpoint 0x88, ~100 ms timeout; writes exactly 12 or 3072 bytes, replies 8 bytes (4 x u16; word 3 status: BUSY 0x04, READY 0x20, AXIS 0x40). Host polls GetVersion/GetListStatus every ~10 ms for READY before pushing the next 3072-byte chunk. Linux udev `ATTRS{idVendor}=="9588", ATTRS{idProduct}=="9899"`.

**Driver:** LightBurn's installer checkbox or `C:\Program Files\LightBurn\EzCad2Driver\dpinst-x64.exe` installs WinUSB for VID 9588 / PID 9899 (+ PID 9980 "Loader"); before: "BJJCZ Device" (EzCad's proprietary LMC driver), after: "USBLMCV2/USBLMCV4" under Universal Serial Bus devices. EzCad2 and LightBurn cannot share the device; revert by uninstalling with "delete driver" and power-cycling. LightBurn Galvo is a separate licence tier (device type "JCZFiber"; EzCad2/EzCad2-Lite boards only, not EzCad3/BSL). A Rust host would use `nusb`/`rusb` on top of the WinUSB driver.

### 2e. File formats

**LightBurn .lbrn / .lbrn2** — proprietary, officially undocumented, plain XML (no compression). LightBurn staff: "not documented, but not horrible to read"; `.lbrn` (FormatVersion 0) was written human-readable; `.lbrn2` (FormatVersion 1, since 0.9.21) is a compacted variant of the same structure (~4x smaller). No SDK. Two of the user's own project files confirm this: a `.lbrn2` has `AppVersion="1.4.04" FormatVersion="1"`, an older `.lbrn` has `AppVersion="0.9.16" FormatVersion="0" MirrorY="True"`.
- Root `<LightBurnProject AppVersion FormatVersion MaterialHeight MirrorX MirrorY>`; MirrorX/Y encode the machine origin used when saving (`MirrorX=False MirrorY=True` = bottom-left origin, `True/False` = top-right). Y is "up" in shape data; SVG converters flip.
- `<Thumbnail Source="<base64 PNG>"/>`; `<VariableText>` (Start/End/Current/Increment/AutoAdvance); `<UIPrefs>` (Optimize_* values, -1 = disabled); `<Notes ShowOnLoad Notes/>`.
- `<CutSetting type="Cut|Scan|Image|Tool|Offset">` and `<CutSetting_Img type="Image">`; fields as child elements with `Value` attributes: `index`, `name`, `minPower`, `maxPower`, `minPower2/maxPower2`, `speed` (mm/s), `priority`, `kerf`, `zOffset`, `numPasses`, `zPerPass`, `perforate`, `dotMode`, `enablePowerRamp/rampLength`, `scanOpt`, `interval`, `angle`, `overScanning`, `lineAngle`, `ditherMode` ... Accept both attribute and child-element forms. Shapes reference layers via `CutIndex`.
- `<Shape Type="Rect|Ellipse|Path|Text|Bitmap|Group|Polygon" CutIndex VertID PrimID Locked>` with child `<XForm>a b c d e f</XForm>` — six floats `m11 m12 m21 m22 m31 m32` = standard 2x3 affine (`x' = a*x + c*y + e`, `y' = b*x + d*y + f`); group XForms compose hierarchically (child first). `Rect`: `W H Cr`, geometry centered at origin; `Ellipse`: `Rx Ry`; `Polygon`: `N Rx Ry`; `Text`: `Str Font H LS LnS Ah Av` + `HasBackupPath="1"` with child `<BackupPath Type="Path">` outline (the only way a third party renders text; one of those files shows `Font="Century Gothic,-1,100,5,50,0,0,0,0,0"`, i.e. a Qt `QFont::toString()`); `Bitmap`: `W H Data`(base64 PNG) `Gamma Contrast Brightness DPI DitherMode Halftone Negative Grayscale`; `Group`: `<Children>`.
- `Path`: **v0** explicit `<V vx vy c0x c0y c1x c1y/>` vertices + `<P T="L|B" p0 p1/>` primitives (`c0` = handle leaving the vertex, `c1` = handle entering). **v1** packs them in `<VertList>`/`<PrimList>` strings: vertices concatenated without separator, each `V<x> <y>` optionally followed by `c0x<v>c0y<v>c1x<v>c1y<v>` and trailing `S` (smooth); bare `c0x1` with no `c0y` = "no control point" placeholder. PrimList = `L<i> <j>` / `B<i> <j>` pairs concatenated (`L0 1L1 2B2 3...`); special values `LineClosed` and empty string (closed loop; cubic where both handles present else line). MeerK40t tokenizes with a regex over `V`, `S`, `(c0x|c0y|c1x|c1y)`, numbers.
